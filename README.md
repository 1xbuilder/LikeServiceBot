# Бот-задачник для менеджеров (Telegram)

Реализация по ТЗ: задачи с приоритетами, пометкой «когда ждать клиента», обязательными
комментариями при закрытии, закреплённым дашбордом, личными уведомлениями,
вечерним контролем и утренним разбором вчерашних задач.

## Файлы

| Файл | Что внутри |
|---|---|
| `bot.py` | точка входа, регистрация хендлеров |
| `config.py` | токен, путь к БД, часовой пояс, дефолтное время напоминаний |
| `db.py` | SQLite: схема и все запросы |
| `parsing.py` | разбор `/task` (исполнитель, приоритет, дата клиента, `!коммент`) |
| `ui.py` | тексты сообщений и inline-клавиатуры |
| `handlers.py` | команды, нажатия кнопок, приём комментариев |
| `menu.py` | кнопочный интерфейс: нижнее меню, конструктор задачи, настройки |
| `check.py` | диагностика подключения к Telegram |
| `jobs.py` | планировщик утренних и вечерних напоминаний |

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env      # вписать BOT_TOKEN и часовой пояс
python bot.py
```

## Настройка в Telegram (обязательные шаги)

1. **@BotFather → /newbot**, получить токен.
2. **@BotFather → /mybots → Bot Settings → Group Privacy → Turn off.**
   Без этого бот не видит обычные сообщения в группе, а значит:
   не сможет сопоставить `@username` с человеком и не примет комментарий,
   отправленный в группу.
3. Добавить бота в группу менеджеров и **сделать администратором** —
   иначе он не сможет закрепить дашборд.
4. Каждый участник один раз пишет боту в личку `/start`.
   Telegram запрещает боту писать первым, так что без этого личные уведомления
   и вечерние напоминания в лички не дойдут. Бот честно сообщит в группе,
   до кого не смог достучаться.

## Интерфейс

Всё управление — кнопками, команды печатать не нужно.

**Нижнее меню** (постоянная клавиатура в группе):

```
        ➕ Новая задача
📋 Задачи        🙋 Мои задачи
🗂 История       ⚙️ Настройки
          ❓ Помощь
```

Появляется само, когда бота добавляют в группу. Если пропало — `/menu`.
В личке меню короче: «Мои задачи» и «Помощь».

**Конструктор задачи.** По кнопке «➕ Новая задача» бот присылает одно
сообщение, которое обновляется на месте по мере выбора:

```
➕ Новая задача

Текст: Продать iPhone 12 клиенту за 25000
Исполнитель: Олег Скиба
Приоритет: 🔴 срочно
Клиент: завтра
Комментарий при закрытии: нужен 💬

[✍️ 1. Изменить текст]
[Игорь] [Ксения Л.]
[✅ Олег Скиба] [Сергей]
[👥 Всем] [🔄 Обновить список]
[✅ 🔴 Срочно] [🟡 Важно] [🟢 Обычно]
[Сегодня] [✅ Завтра] [Послезавтра]
[📅 Своя дата] [✖️ Без даты]
[💬 Комментарий нужен ✅]
[✅ Создать] [✖️ Отмена]
```

Кнопки идут в том же порядке, что и пункты 1–5 в описании.

Текст задачи пишется сообщением — бот сам его подхватывает и удаляет из чата,
чтобы не мусорить. Всё остальное — тапы. «📅 Своя дата» тоже принимает
произвольный текст вроде «после обеда».

### Откуда берётся список исполнителей

Telegram не даёт боту запросить полный состав группы — это ограничение платформы,
обойти его нельзя. Поэтому список наполняется тремя путями:

1. **Администраторы группы** — их бот запрашивать умеет. Список обновляется сам
   при открытии конструктора и по кнопке «🔄 Обновить список».
   Самый быстрый способ собрать всех: выдать менеджерам права админов
   (достаточно любых, хоть только «Закрепление сообщений»).
2. **Кто вошёл в группу при работающем боте** — подхватываются автоматически.
3. **Кто написал любое сообщение в чат** — тоже запоминаются.

Если кого-то не хватает: либо сделать админом и нажать «🔄 Обновить список»,
либо попросить отправить в чат любое сообщение.

**Настройки** — тот же принцип: время сдвигается кнопками −1 ч / −15 м / +15 м / +1 ч,
включение и выключение переключателем. Печатать время не нужно.

**История** — кнопки 7 / 14 / 30 дней.

## Команды

Остались как альтернатива для тех, кому быстрее печатать.

```
/task @user [приоритет] [дата клиента] [!коммент] текст
/list        активные задачи группы
/my          мои задачи (в личке — из всех групп)
/history 7   закрытые и отменённые за N дней, с комментариями
/dashboard   пересобрать и заново закрепить дашборд
/settings    текущие настройки напоминаний
/setevening 20:00
/setmorning 9:45
/settoggle evening off
/skip        отменить начатый ввод комментария
```

Примеры:

```
/task @Ksenia_L Перезвонить клиенту
/task @Oleg_Skiba срочно завтра 12:00 !коммент Продать iPhone 12 клиенту за 25000
/task all важно Обновить цены на сайте
```

## Как разбирается команда

Порядок такой же, как в ТЗ, всё кроме исполнителя и текста — необязательное.

- **приоритет** — `срочно` / `важно` / `обычно` (по умолчанию «обычно»), 🔴 / 🟡 / 🟢.
- **дата клиента** — чисто текстовая пометка, на поведение задачи не влияет.
  Распознаются слова (`сегодня`, `завтра`, `послезавтра`, дни недели),
  время с двоеточием (`12:00`) и даты через точку (`01.08`).
  Время пишется только с двоеточием, потому что `01.08` иначе не отличить от `1:08`.
  Любую другую формулировку можно взять в кавычки: `/task @Igor "после обеда" Позвонить в сервис`.
- **`!коммент`** — задача закрывается только после текстового комментария.
- Вместо `@user` можно **ответить командой на сообщение человека** — удобно,
  если у него нет юзернейма.

## Поведение

- **Создание.** Карточка уходит в группу с кнопками «✅ Выполнено» (или
  «✅ Выполнено (нужен комм.)») и «✖️ Отменить», плюс копия в личку исполнителю.
  Для `all` — в лички всем, кто нажимал `/start`.
- **Закрытие.** Обычная задача закрывается мгновенно. Задача с `!коммент` —
  бот просит текст, и только после него ставит ✅. Комментарий видно в карточке
  и в `/history`.
- **Дашборд.** Закреплённое сообщение обновляется при любом изменении.
  Кнопка напротив каждой задачи; если задача требует комментария — запросит его.
- **Просрочка.** Задача, не закрытая за сутки с постановки, помечается 🔥 и уходит
  в отдельный блок «Просрочено» во всех списках и в закрепе. Дальше бот напоминает
  о ней **в личку исполнителю**, пока её не закроют:
  срочные — каждые 30 минут, важные — каждые 2 часа, обычные — каждые 12 часов.
  Напоминания идут только в рабочем окне: с времени утреннего напоминания
  до 22:00 — иначе срочная задача будила бы человека ночью каждые полчаса.
  В напоминании три кнопки: закрыть, отложить на час, отменить.
  Всё это настраивается: пороги в `.env`, окно и выключатель — кнопками в «⚙️ Настройки».
- **Вечер (19:30).** Список незакрытых задач в группу и в лички, с ✅ и ✖️.
- **Утро (09:45).** Задачи, оставшиеся со вчера, с кнопками «⏭ Перенести» и «✖️ Отменить».
  «Перенести» просто убирает кнопку — задача остаётся активной.
- Настройки времени может менять любой участник, время считается в `TIMEZONE`.

## Отладочные команды (только при `DEBUG=1`)

```
/testevening   запустить вечерний контроль сейчас
/testmorning   запустить утреннее напоминание сейчас
/testnag       разослать напоминания о просрочке сейчас (мимо тихих часов)
/backdate 3    сделать задачу #3 «вчерашней»
/known         кого бот запомнил и кому может писать в личку
```

Нужны, чтобы проверить напоминания не дожидаясь 19:30 и 09:45.
Перед выкладкой на прод поставь `DEBUG=0` в `.env`.

## Если бот не стартует

Запусти диагностику — она по шагам проверит DNS, TCP, прокси и токен:

```bash
python check.py
```

**`telegram.error.TimedOut` / `httpcore.ConnectTimeout` при запуске.**
Соединение с `api.telegram.org` не устанавливается — код тут не при чём.
В ряде стран Bot API блокируется провайдером. Варианты:

- VPN на всём компьютере — годится для теста;
- прокси только для бота: `PROXY_URL=socks5://user:pass@host:1080` в `.env`
  (для socks5 доустанови `pip install "httpx[socks]"`);
- VPS за пределами блокировки — правильный вариант для работы. Боту всё равно
  нужно работать круглосуточно, иначе напоминания в 09:45 и 19:30 не сработают.

**`401 Unauthorized`** — токен неверный или отозван, возьми свежий у @BotFather.

**`ZoneInfoNotFoundError`** — в `TIMEZONE` нужно полное имя из базы IANA
(`Asia/Omsk`, а не `Omsk`).

## Развёртывание на сервере

```bash
adduser --system --group --home /opt/taskbot taskbot
cd /opt/taskbot
# распаковать сюда файлы бота
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env        # токен, TIMEZONE, DEBUG=0
chown -R taskbot:taskbot /opt/taskbot

cp taskbot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now taskbot
systemctl status taskbot
journalctl -u taskbot -f                 # смотреть логи
```

Перед первым запуском на сервере полезно прогнать `venv/bin/python check.py` —
он проверит сеть и токен до того, как бота начнут ждать люди.

**Обязательно `DEBUG=0` в `.env`.** Иначе `/backdate` и `/testnag` доступны всей группе.

**Только один запущенный экземпляр.** Если бот параллельно работает на ноутбуке и
на сервере, Telegram начнёт отдавать обновления то одному, то другому, и в логах
пойдут ошибки `Conflict`. Перед запуском на сервере останови локальный.

**Бэкап.** Всё состояние в одном файле `tasks.db`. Достаточно раз в сутки:

```
sqlite3 /opt/taskbot/tasks.db ".backup /var/backups/taskbot-$(date +%F).db"
```

Копировать файл на живом боте через `cp` не стоит — база в режиме WAL,
`.backup` делает это корректно.

**Если сервер лежал в момент напоминания**, эта конкретная рассылка пропускается —
планировщик не догоняет пропущенное время. Просроченные задачи всё равно всплывут:
напоминания о просрочке идут по своему циклу и подхватят их на следующей проверке.

## Технические заметки

- Кнопки в дашборде и напоминаниях ограничены 40 задачами на сообщение
  (`MAX_DASHBOARD_TASKS` в `config.py`) — это лимит Telegram по размеру клавиатуры.
  Остальные видны в `/list`.
- Закрыть задачу может любой участник, а не только исполнитель — по ТЗ «все равны».
- База — SQLite (`tasks.db`), запросы синхронные. Для группы из 5 человек этого
  достаточно с большим запасом; при переезде на десятки чатов стоит перейти на
  `aiosqlite` или Postgres.
- Одна база спокойно обслуживает несколько групп: задачи, дашборд и настройки
  привязаны к `chat_id`.
- Для автозапуска на сервере — обычный systemd-юнит с `Restart=always`;
  состояние целиком в БД, перезапуск ничего не теряет.
